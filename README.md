# Response Mocker

Расширение для Chrome (и других браузеров на Chromium), которое подменяет ответы `fetch` и `XMLHttpRequest` по заданным правилам. Работает полностью локально: без аккаунтов, серверов, телеметрии и пробного периода.

## Установка

1. Распакуйте архив.
2. Откройте `chrome://extensions`.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение» и выберите папку `response-mocker`.

Нужен Chrome 111 или новее (расширение использует контент-скрипты с `world: "MAIN"`).

## Быстрый старт

1. Нажмите на значок расширения и выберите «Открыть редактор».
2. Нажмите «Новое правило».
3. Укажите адрес запроса, например `/api/users`, и тело ответа.
4. Нажмите «Сохранить».
5. Перезагрузите страницу, на которой нужна подмена.

В консоли страницы каждая подмена пишется с пометкой `[Response Mocker]`, так видно, что правило сработало.

## Поля правила

| Поле | Что делает |
|---|---|
| Название | Имя в списке правил и в консоли |
| Как искать адрес | «Содержит», «Равен», «Шаблон с `*`» или «Регулярное выражение» |
| Метод | `ANY`, `GET`, `POST`, `PUT`, `PATCH`, `DELETE` |
| Адрес запроса | Что искать. Сравнивается с полным адресом запроса, например `https://site.com/api/users?id=1` |
| Только на страницах, адрес которых содержит | Ограничивает правило страницами, адрес которых содержит эту строку. Пусто — на всех страницах |
| Код ответа | От 200 до 599 |
| Текст статуса | Необязательно, например `OK` |
| Задержка, мс | Через сколько миллисекунд отдать ответ |
| Content-Type | Например `application/json` |
| Заголовки ответа | По одному в строке в формате `Имя: значение` |
| Тело ответа | Любой текст. Для `application/json` проверяется на корректность |

Правила проверяются сверху вниз, срабатывает первое подходящее.

### Примеры адресов

- Содержит: `/api/users` подойдёт и для `https://site.com/api/users?page=2`.
- Шаблон: `https://site.com/v*/items` подойдёт для `/v1/items` и `/v2/items`.
- Регулярное выражение: `/orders/\d+$` подойдёт для `/orders/77`.

## Импорт и экспорт

Кнопки «Экспорт» и «Импорт» в редакторе сохраняют правила в JSON-файл и загружают их обратно. При импорте правила добавляются к существующим.

## Ограничения

- Подменяются только запросы, которые делает сама страница через `fetch` и `XMLHttpRequest`. Запросы расширений, service worker и загрузка ресурсов браузером (картинки, CSS, скрипты, документы) не перехватываются.
- Запросы, отправленные до того, как расширение передало правила странице, подменить нельзя. Подмена начинается через долю секунды после старта страницы. Если правило создано или изменено, перезагрузите страницу.
- Синхронные XHR работают, но если правила ещё не загружены, такой запрос уйдёт настоящим.
- Заголовки запроса, редиректы и блокировка запросов не поддерживаются.

## Приватность

Правила хранятся в `chrome.storage.local` и никуда не отправляются. Расширение не делает сетевых запросов.

Контент-скрипт передаёт странице только включённые правила, подходящие под её адрес. Правила без ограничения по странице получают скрипты любого сайта, где расширение работает, поэтому не храните в теле подмены секреты. Для чувствительных правил заполните поле «Только на страницах…».

## Устройство

| Файл | Роль |
|---|---|
| `manifest.json` | Манифест Manifest V3, разрешение только `storage` |
| `inject.js` | Работает в контексте страницы, подменяет `fetch` и `XMLHttpRequest` |
| `bridge.js` | Передаёт правила из `chrome.storage` в страницу через `postMessage` |
| `popup.html`, `popup.js`, `popup.css` | Попап: общий выключатель и переключатели правил |
| `options.html`, `options.js`, `options.css` | Редактор правил |
| `ui.css` | Общие стили, светлая и тёмная тема |
